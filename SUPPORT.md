# Locoris Support

Locoris is maintained by a solo developer. Choosing the right channel keeps
questions visible, security reports private, and reproducible bugs actionable.

## Questions and self-hosting help

Use [GitHub Discussions](https://github.com/locoris/locoris/discussions) for
setup questions, self-hosting help, workflows, and early product ideas. Search
existing discussions before starting a new one.

Community support is best effort and does not provide an uptime or response
time guarantee.

## Reproducible bugs

Use the repository's **Bug report** issue form. Include the Locoris version,
platform, affected product area, synchronization method, and minimal steps to
reproduce the problem.

Never upload a real vault, backup, credential, recovery secret, encryption key,
access token, or unredacted log. Create synthetic data for reproduction.

## Feature requests

Use the **Feature request** form for a focused user problem. Broad concepts may
start as a Discussion so the scope can be understood before implementation.

## Security and privacy

Do not open a public issue for a suspected vulnerability. Follow
[SECURITY.md](SECURITY.md) and use GitHub private vulnerability reporting.

## Locoris Cloud accounts and billing

Do not publish account identifiers, invoices, payment details, or private cloud
diagnostics in this public repository. Use the private support route presented
inside the Locoris Cloud account experience. Public issues may cover client
behavior only when they can be reproduced with synthetic data.
