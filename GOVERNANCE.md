# Locoris Governance

Locoris uses a lightweight, maintainer-led governance model. It is designed for
a solo-maintained project today while leaving a clear path for trusted
maintainers and a broader community later.

## Principles

- User ownership, privacy, portability, and local-first operation come first.
- The public application and self-hosted server remain usable without Locoris
  Cloud.
- Security and data compatibility take priority over release speed.
- Decisions and their material trade-offs should be visible in issues,
  discussions, pull requests, release notes, or public roadmap documents.
- Funding does not buy control over technical decisions or access to user data.

## Project lead

The project lead is `angrein`, the original author and current maintainer. The
project lead is responsible for product direction, releases, repository access,
security coordination, licensing, and the final decision when consensus cannot
be reached.

This is a responsibility model, not a promise that every request will be
accepted or implemented.

## Contributors and maintainers

Anyone may contribute under the process in [CONTRIBUTING.md](CONTRIBUTING.md).
Repeated, constructive contributors may be invited to maintain a defined area.
Maintainer access is granted gradually and may be removed when it is no longer
needed or when project security requires it.

No contributor is required to provide unpaid support or accept work outside the
scope they choose.

## Decisions

Routine fixes and small improvements are decided during review. Significant
changes should begin with a public issue or discussion and include:

- the user problem and intended outcome;
- privacy, security, and data-migration effects;
- cross-platform and accessibility effects;
- alternatives considered;
- compatibility and rollback plans where user data is involved.

The project lead seeks practical consensus. When views remain divided, the
project lead records the decision and its rationale and makes the final call.

## Releases and security

Only authorized maintainers may publish official releases or use Locoris
signing credentials. Security reports are handled privately according to
[SECURITY.md](SECURITY.md). Public disclosure is coordinated after users have a
reasonable path to an update.

## Funding

Sponsorships and grants support work on the public project. Where a funding
platform provides a public ledger, funded goals and material expenses should be
described there. Grant-funded deliverables promised as open source are released
in the public repository under its applicable license.

Locoris Cloud is a separate commercial service. Its revenue may fund the public
project, but cloud customers do not receive governance authority over the
open-source project.

## Governance changes

Changes to this document follow the same public review process as other
significant project changes. If stewardship expands, this model may be replaced
with a maintainer council or foundation structure after responsibilities,
security access, and continuity are documented.
