# Locoris Server 0.1.7

## Summary

Distribution metadata release for Locoris Server desktop packages and signed multi-architecture Docker installations.

## Security

Desktop artifacts receive unified checksums, a production dependency SPDX SBOM, and GitHub attestations. The Docker manifest is keyless-signed with Cosign through GitHub OIDC, while each architecture includes BuildKit provenance and SBOM attestations.

## Added

- Automated validation that the published server SBOM contains the production dependency graph.

## Improved

- Docker setup and registry actions now use their Node 24 releases and receive the metadata permission required by BuildKit records.
- The standalone SPDX document is generated from the locked server workspace dependency graph.

## Fixed

- The server release no longer publishes a nearly empty source-only SBOM.
- Docker release jobs no longer depend on deprecated Node 20 action runtimes.

## Compatibility

- API contract 1, sync protocol 1, pairing protocol 1, storage schema 2.
- Minimum Locoris client version: 1.0.0.
- Desktop: Apple Silicon macOS, Windows x64, and Linux x64.
- Docker: Linux amd64 and arm64.

## Migration

No storage migration is introduced. Existing SQLite metadata, vault files, device credentials, and legacy JSON migration markers remain compatible.

## Update

Back up the complete data directory first. Desktop users install 0.1.7 over the current application. Docker users pin and pull `ghcr.io/locoris/locoris-server:0.1.7`, then recreate the service against the same volume.

## Rollback

Stop 0.1.7, restore the complete pre-update data-volume backup as one unit, and reinstall the previous verified package or immutable Docker tag.

## Known issues

macOS and Windows desktop packages are not yet backed by paid platform certificates. Docker/NAS remains the recommended always-on production installation.

## Verification

Verify desktop artifacts against `SHA256SUMS.txt` and GitHub attestations. For Docker, deploy the manifest digest published in this release and verify its Cosign identity against the protected Locoris server release workflow.
