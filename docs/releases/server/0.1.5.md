# Locoris Server 0.1.5

## Summary

Production distribution foundation for self-hosted Locoris synchronization across desktop packages and a signed multi-architecture Docker image.

## Security

Desktop artifacts receive checksums, an SPDX SBOM, and GitHub attestations. The Docker manifest is keyless-signed with Cosign through GitHub OIDC, while each architecture includes BuildKit provenance and SBOM attestations.

## Added

- Native `linux/amd64` and `linux/arm64` Docker images behind one versioned manifest.
- Runtime compatibility contract in health, capabilities, and pairing responses.
- Non-destructive update availability checks against official Locoris Server releases.

## Improved

- Desktop packages are smoke-tested after packaging on macOS Apple Silicon, Windows x64, and Linux x64.
- The server dashboard explains update status and the correct desktop or Docker update path without silently installing anything.
- Checksum generation excludes stale artifacts from earlier local builds.

## Fixed

- The packaged Electron preload now loads through the correct CommonJS boundary.
- macOS ad-hoc packages include the hardened-runtime entitlements required by Electron and pass strict code-signature verification.

## Compatibility

- API contract 1, sync protocol 1, pairing protocol 1, storage schema 2.
- Minimum Locoris client version: 1.0.0.
- Desktop: Apple Silicon macOS, Windows x64, and Linux x64.
- Docker: Linux amd64 and arm64.

## Migration

No storage migration is introduced by 0.1.5. Existing SQLite metadata, vault files, device credentials, and legacy JSON migration markers remain compatible.

## Update

Back up the complete data directory first. Desktop users install the new package over the current application. Docker users pin and pull `ghcr.io/locoris/locoris-server:0.1.5`, then recreate the service against the same volume.

## Rollback

Stop 0.1.5, restore the complete pre-update data-volume backup as one unit, and reinstall the previous package or immutable Docker tag. Never mix SQLite and vault files from different backup generations.

## Known issues

macOS and Windows desktop packages are not yet backed by paid platform certificates. Docker/NAS remains the recommended always-on production installation.

## Verification

Verify desktop artifacts against `SHA256SUMS.txt` and GitHub attestations. For Docker, deploy the manifest digest published in this release and verify its Cosign identity against the protected Locoris server release workflow.
