# Locoris 1.0.54

## Summary

Cloud session and vault-binding reliability release for web, iOS Web App, Android, macOS, and Windows.

## Security

Locoris continues to keep browser bearer credentials in memory while using the same-origin HttpOnly account session for silent renewal. Native clients continue to use the application-owned private credential store introduced in 1.0.53.

## Added

- Regression coverage for exact cloud-vault identity recovery, duplicate local identities, and already connected remote vaults.

## Improved

- Signing in to Locoris Cloud now reconciles the current device, local vault identities, cloud vaults, and device-scoped sync credentials as one flow.
- Returning to an existing browser or native session silently renews eligible account credentials before cloud synchronization starts.
- A recovered cloud binding is synchronized immediately instead of waiting for the next edit, page reload, or manual sync action.

## Fixed

- A local vault marked as Cloud no longer remains disconnected after signing out and back in when its stable cloud identity still exists.
- Locoris no longer asks an authenticated user to manually bind the same vault again merely because the device-scoped sync credential is missing or stale.
- Automatic recovery no longer creates a second local binding to an already connected remote vault.
- Ambiguous duplicate local identities are left for explicit user resolution instead of being matched automatically.

## Compatibility

- macOS: Apple Silicon only.
- Windows: Windows 10/11 x64.
- Android: direct APK signed by the stable Locoris release certificate.
- Hosted web application and installed iOS Web App: updated by the web deployment.
- Locoris Server: sync protocol version 1.
- Locoris Cloud: 0.1.4 recommended.

## Migration

No vault-data migration is required. Existing local and cloud vault identities are reused. When a valid account refresh session exists, Locoris repairs the device binding automatically.

## Update

Install the new build over the existing desktop or Android application. The hosted web application updates automatically; an installed iOS Web App may need to be fully closed and reopened once after deployment.

## Rollback

Reinstall the previous verified artifact. Local and cloud vault data remain compatible, but a missing device binding may again require manual reconnection on 1.0.53.

## Known issues

A genuinely expired, revoked, or cleared account refresh session still requires a new sign-in. In that state the web application returns to the sign-in screen instead of leaving Cloud controls in a partially authenticated state. macOS and Windows builds are not yet backed by paid platform certificates, so Gatekeeper and SmartScreen can show an unknown-developer warning.

## Verification

Compare the complete SHA-256 digest with `SHA256SUMS.txt`, then run `gh attestation verify <file> --repo locoris/locoris`. Android users can additionally compare the published signing-certificate fingerprint.
