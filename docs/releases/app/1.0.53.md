# Locoris 1.0.53

## Summary

Desktop credential reliability release for Apple Silicon macOS and Windows x64, with unchanged Android and hosted web behavior.

## Security

Desktop synchronization credentials are stored in a dedicated private SQLite database inside the Locoris application-data directory. The database uses secure deletion, a private parent directory, and owner-only file permissions on Unix platforms.

## Added

- Regression coverage for desktop secret creation, reading, deletion, and private filesystem permissions.

## Improved

- Desktop credentials are now loaded through one predictable application-owned store instead of repeatedly invoking the operating-system credential prompt during startup and connection management.
- Opening Locoris and removing a synchronization method no longer causes a sequence of macOS Keychain password dialogs.

## Fixed

- macOS no longer asks for the login Keychain password multiple times when Locoris starts after an unsigned application update.
- Secret reads for several synchronization connections no longer produce one system authorization dialog per stored credential.

## Compatibility

- macOS: Apple Silicon only.
- Windows: Windows 10/11 x64.
- Android: direct APK signed by the stable Locoris release certificate; native secure storage is unchanged.
- Hosted web application: browser session and encrypted local storage behavior are unchanged.
- Locoris Server: sync protocol version 1.
- Locoris Cloud: 0.1.4 recommended.

## Migration

Local vault data does not require migration. On macOS or Windows, a synchronization connection whose credential exists only in the previous operating-system credential store may require one sign-in after updating. The connection and vault data remain in place; enter the credential again when Locoris requests renewed access.

## Update

Install the new build over the existing application or accept the desktop updater when offered. Android users do not need this desktop-specific update to preserve secure-storage behavior.

## Rollback

Reinstall the previous verified artifact. Local vaults remain compatible. Credentials entered in 1.0.53 may need to be entered again after rollback because earlier versions read a different desktop credential store.

## Known issues

Existing entries in the previous macOS Keychain or Windows credential store are left untouched and are not imported automatically, because reading them could recreate the system password prompts this release removes. macOS and Windows builds are not yet backed by paid platform certificates, so Gatekeeper and SmartScreen can show an unknown-developer warning.

## Verification

Compare the complete SHA-256 digest with `SHA256SUMS.txt`, then run `gh attestation verify <file> --repo locoris/locoris`. Android users can additionally compare the published signing-certificate fingerprint.
