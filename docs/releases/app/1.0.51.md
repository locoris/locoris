# Locoris 1.0.51

## Summary

Session and cloud-sync reliability release for Apple Silicon macOS, Windows x64, Android, and the hosted web application.

## Security

Browser refresh credentials remain in a secure first-party HttpOnly cookie. Short-lived access credentials are restored without exposing the persistent session to application JavaScript.

## Added

- Production Cloudflare Pages routing for the hosted application and its same-origin cloud API proxy.
- Explicit recovery states for an expired, revoked, or unavailable hosted cloud session.

## Improved

- Browser sessions survive normal tab, browser, and device restarts while remaining bounded by idle and absolute expiry limits.
- Cloud sync resumes more reliably after the application returns online or becomes visible again.
- Account, sync, and web-access surfaces now share the same hosted-session state instead of showing conflicting availability messages.

## Fixed

- Hosted web sessions no longer fall back to a transient sign-in screen during normal refresh recovery.
- A valid cloud refresh session can restore access after the in-memory access token expires.
- Revoked or rejected credentials now lead to a clear reauthentication flow instead of leaving a stale available state.

## Compatibility

- macOS: Apple Silicon only.
- Windows: Windows 10/11 x64.
- Android: direct APK signed by the stable Locoris release certificate.
- Locoris Server: sync protocol version 1.
- Locoris Cloud: 0.1.4 recommended.

## Migration

No local-vault migration is required. Existing local vaults and sync bindings remain in place.

## Update

Install the new build over the existing application or accept the signed desktop updater when offered. Android updates require the existing installation to use the same Locoris signing certificate.

## Rollback

Reinstall the previous verified artifact. Local vault data does not require a rollback migration.

## Known issues

macOS and Windows builds are not yet backed by paid platform certificates. Gatekeeper and SmartScreen can therefore show an unknown-developer warning; follow the official direct-install guide after verifying the artifact.

## Verification

Compare the complete SHA-256 digest with `SHA256SUMS.txt`, then run `gh attestation verify <file> --repo locoris/locoris`. Android users can additionally compare the published signing-certificate fingerprint.
